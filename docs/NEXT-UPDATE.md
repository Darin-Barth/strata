# Queued for the next update

Changes committed on master since the last release (**v1.3.0**; notes in the GitHub release) that haven't been released yet. Policy: changes ship together in one update (merge to `master` + new `.mrpack` release + server restart); only a critical hotfix goes out on its own. Queued work can be backed up to the GitHub branch `next-update` (`git push origin master:refs/heads/next-update`); the server only follows `master`.

## Changes
- **Structures spread out 1.5x (Darin, Nov 7; tested on the test server Nov 7):** structures generated too close together (about one every 5-6 chunks on the surface, a third of them Moog's Voyager's 116 small structure types). Structurify's global spacing modifier is now on at 1.5 (`config/structurify.json`). Moog's and Integrated mods (IDAS, Integrated Villages) use their own placement maths that Structurify doesn't touch (same seed: identical positions with it on), so `tools/build_structure_spacing.py` writes their 233 structure sets into `kubejs/data` with spacing and separation x1.5. Same-seed test, median distance to the nearest structure from six points: Moog's haystack 341 -> 505 m, Moog's bench 880 -> 1,250 m, IDAS abandoned house 2.3 -> 3.2 km, Dungeons and Taverns underground house 246 -> 376 m. Pillager outposts stay at vanilla spacing: under Structurify they went from about 2 km apart to 5 km at 1.25x and 11 km at 1.5x. Boot errors unchanged. Only land generated after the update spreads out.
- **Lifepod Console fixed (found and tested Nov 7):** right-clicking the console in the Abyssal Plain did nothing: its script cancelled the click first, and in KubeJS `event.cancel()` ends the handler, so the surfacing teleport never ran (`kubejs/server_scripts/abyssal_rules.js`; the cancel now comes last, and no other script has code after a cancel). Tested from the Abyssal Plain: old script, the player stayed; fixed script, the player surfaced at their last overworld spot.
- **Cloudy Temple server crash fixed (Nov 6; tested on the test server Nov 6):** the server crashed at 21:34 on Nov 6 with "Accessing LegacyRandomSource from multiple threads", and the log at 21:41 shows the cause: Legendary Monsters' Stratling (the Cloudy Temple trader) fills its trades from the world's random generator whenever it loads, and when world generation places a temple that happens on a generation thread, alongside the server thread. `tools/build_cloudy_temple.py` writes the pack's copy of the 5 temple pieces with each Stratling (8) replaced by a marker, and `kubejs/server_scripts/strata_stratling.js` puts a Stratling in its place on the server thread once the chunk is in the world. Tested by generating a temple: 12 markers turned into 12 Stratlings with their facing and full trades (enchanted book included), no threading errors. Temples already generated are unchanged. A second crash at 21:43 (entity tracking map changed mid-tick, `ChunkMap.tick`) is not explained by this and stays unconfirmed: watch for it.
- **Infinite reward chests fixed (Nov 6; tested on the test server Nov 6):** Panascraft RPG's Silence Death dungeon has mob spawners for Echo Kings and Sculk Sentinels, and each one that dies places a reward chest (Lootr chest: totems, enchanted golden apples, diamond apples, echo shards...), so the dungeon gave unlimited loot. `kubejs/server_scripts/strata_spawner_chests.js` removes the chest one tick after either mob dies (they have no other source). Their own drops stay, as do the dungeon's chests, the boss's reward and the reward chests from wild mini-bosses (tested: Echo King and Sentinel leave nothing, a Speeder Mutant Zombie still leaves its Lootr chest; KubeJS 31/31 scripts, 0 errors). Server-only script; chests already placed in the world stay.
- **New Create add-ons (Darin, Nov 6; tested on the test server Nov 6):** Create: Blocks & Bogies 1.0.8 (31 more bogie styles in Steam 'n' Rails' bogie menu), Create: Bells & Whistles 0.4.7 (train decoration and parts, 36 items), Create: Liquid Fuel 3.0.0 (pipe lava, C&A seed oil or bioethanol into a Blaze Burner; bioethanol superheats). A test burner took 1,000 mB of lava through its fluid side and stayed heated. Diesel Generators' fuels also feed burners (`kubejs/data/createliquidfuel/data_maps/fluid/liquid_fuel.json`, Darin): plant oil heats like C&A seed oil; ethanol (like C&A bioethanol), biodiesel, gasoline and diesel superheat, the better fuels lasting longer. Tested: all six fuels accepted, crude oil refused. Liquid Fuel's CurseForge upload is a separate build, mapped in `tools/curseforge-manual.json`.
- **JEI back: machine recipes show in EMI again** (tested Nov 4). Create (pressing, mixing, compacting, deploying...), Immersive Engineering, Diesel Generators (plant oil, fermenting, distillation), Apprentice Codex's Essence Smoker and many others only register their recipes with JEI; EMI shows them when JEI is installed (EMI hides JEI's own screen). Test join: 261 JEI categories read, 355,783 recipes in EMI (247,848 before), no kick. JEI 19.69.0.457 is pinned (19.70 crashes against All The Leaks' JEI mixin) with MezzConfig. Cost: joining takes longer and the first minute or so is choppy (JEI froze the client 32 s on a fast PC; EMI's reload went from about 57 s to 108 s).
  **Server start option needed at release:** JEI's freeze is why players timed out on Oct 25: the server drops a client that sends nothing for 30 s. Add `-Dneoforge.readTimeout=120` to the server's Java options (`JVM_OPTS` in the Docker setup) *before* restarting on this version, or slower PCs get kicked while joining. The same limit dropped a far-away player (Europe) on Nov 5: when she joins an empty server, the step after sign-in takes about 45 s instead of 8 s, and one try timed out at 58 s.
- **Server freezes fixed (already live, Nov 1):** the server crashed three times in 15 minutes (12:44, 12:52, 12:56): its main thread spent over 60 s loading saved chunks and the watchdog shut it down. Distant Horizons on the server (`generatorPlan = "SURFACE_THEN_CHUNKS"`) loaded real chunks for every player's distant view, and a player exploring far north flooded it. Now `SURFACE_ONLY`: distant land is drawn from a quick terrain pass on DH's own threads, no chunk loads. Changed on the live server directly (backup `config/DistantHorizons.toml.bak-20261101-1257`) and in the pack's copy for new installs. Distant views lose trees and buildings past the normal view distance.
- **Crimson Blade crash fixed (tested Nov 7):** Forsaken Relics 1.0.1 crashed the server five times (Oct 30 22:40; Nov 1 01:31, 01:42, 01:43, 01:48): a mob killed by the blade's Bleed curse changes the mod's list of cursed mobs while the mod is walking through it (`ConcurrentModificationException` in `CrimsonBladeItem.tickCurses`). `kubejs/server_scripts/strata_crimson_blade.js` cancels a bleed hit that would kill (indirect magic from the blade's owner, or plain magic when the owner isn't in that dimension, on ticks divisible by 20) and deals it one tick later, outside that loop. The first version never worked: KubeJS hides `getMsgId()` (it errored on every hit in the game) and `event.cancel()` ends the handler, so the delayed hit was never scheduled. Test: a fake player cursed six husks with the blade and they were set to 1 health: without a working script the server crashed (3 times), with it no crash in 5 rounds and every husk died. Server-only script.

## Release test (1.4.0, Nov 7)
- **Fresh install:** server from the repo boots (13/13 startup, 31/31 server scripts, 0 errors; boot error types match the 1.3.0 server's except a first-boot-only "jupiter.json" note). Client from `Strata-1.4.0.mrpack`: dependency check shows nothing new beyond JEI's usual Minecraft-range warning; joined, title screen reads "Strata 1.4", no kick (JEI 29-56 s, EMI item groups 37-72 s).
- **Upgrade:** a copy of the live server's data (world, mods, configs) upgraded by packwiz installed exactly the queued files and 5 mods, booted with 31/31 scripts and 0 errors and no new error types, ran at 20 TPS with a player on; killing Echo Kings at the real Silence Death dungeon left no chest.
- **Packaging:** `packwiz mr export` (1.4.0 .mrpack) and the CurseForge Action's steps run locally (438 files, Drive-By-Wire in overrides) both succeed; `curseforge_ids.py` maps all 391 Modrinth files.
- **Client memory:** at 8 GB the client fills its heap within minutes of joining (1.3.0 already sits at 93-99% after collections on the test client; JEI adds a few hundred MB more) and froze once until the server timed it out. At 10 GB it stalls only while JEI/EMI load, then runs clean; at 12 GB it is comfortable. README and JOINING now say 10 GB minimum, and the release notes say so first.
- **Found and fixed during the test:** the Crimson Blade workaround never ran (now fixed and tested); the Lifepod Console never worked (fixed and tested).

## Release checklist
1. Check `version` in `pack.toml` and the version line in `config/fancymenu/customization/strata_title_screen.txt` (both the new version).
2. `python -I tools/curseforge_ids.py` (re-adds CurseForge IDs after mod updates; fix any "no longer used" line in
   `tools/curseforge-manual.json`), `packwiz refresh`, commit, `git push` (master, and sync `next-update`). Check no stray files sit under the server's `kubejs/data`: KubeJS refuses to start on an uppercase file name there.
3. `packwiz mr export -o build/Strata-<version>.mrpack`; `gh release create v<version>` with the notes below.
   The CurseForge Action (`.github/workflows/curseforge.yml`) then builds `Strata-<version>-curseforge.zip`, attaches
   it to the release and, when the repo variable `CURSEFORGE_UPLOAD` is `true`, uploads it to CurseForge with the
   release notes as the changelog (CurseForge reviews it before it goes public). One-time setup by the repo owner: secret
   `CURSEFORGE_TOKEN`, variables `CURSEFORGE_PROJECT_ID` and `CURSEFORGE_UPLOAD`; leave the upload off until
   Drive-By-Wire is on CurseForge's approved list (requested), or CurseForge rejects the file. To upload a
   release that's already out: Actions → CurseForge → Run workflow with its tag.
4. On the server, add `JVM_OPTS: "-Dneoforge.readTimeout=120"` under `environment:` in `/opt/minecraft/strata/compose.yml` (back it up first); a compose change needs `docker compose up -d`, not just a restart. Wait about 5 minutes for GitHub's raw-file cache, then restart the server (Quarry restart, or `docker compose restart`
   in `/opt/minecraft/strata`). Check the log for `Loaded N/N KubeJS server scripts ... 0 errors`.
5. Tell the group to import the new `.mrpack`.

Note: `config/DistantHorizons.toml` and `config/cameraoverhaul.toml` are `preserve = true`, so players who already have
them keep their own copy. Changes there only reach new installs.
